# STEP2 テキスト入力（深掘り付き品質担保プロセス）

## 進め方
1. **Phase A（コンテンツ戦略の確認）**：テキストを集める前に、STEP1の分析結果をもとにコンテンツの方向性を合意する。
2. **Phase B（必須キーの回収 + 深掘り）**：各テキストに対してステップバッククエスチョンで品質を引き上げる。
3. **Phase C（一貫性チェック + 生成前確認）**：集めたテキスト全体の整合性を検証し、最終確認する。

---

## Phase A：コンテンツ戦略の確認

テキスト回収の前に、STEP1で合意した以下をユーザーに再提示し、ブレがないことを確認する。

```
【コンテンツ方針（STEP1分析から）】
- ターゲット：___
- 訪問者が最初に知りたいこと：___
- 信頼構築に必要な要素：___
- CTA：___
- トーン：___
```

ステップバック：**この方針に沿って文章を書くとき、「御社らしい言い回し」や「業界特有の表現」で使いたいものはありますか？**
ステップバック：**逆に、使いたくない表現・避けたい言い回しはありますか？（例：「ソリューション」は使わない、カタカナ語を減らしたい等）**

---

## Phase B：必須キーの回収（深掘り付き）

選択済みのIA Blueprintの `requiredTextKeys` を列挙し、ユーザーから順に回収する。
各キーについて、ただ受け取るだけでなく、以下の深掘りプロセスを適用する。

### 深掘りルール（すべてのテキストキーに適用）

#### Hero見出し / サブ見出し
- ステップバック：**その見出しは「ターゲットの課題」を起点にしていますか？ 自社視点（「私たちは〜」）ではなく、顧客視点（「あなたの〜を解決」）になっていますか？**
- ステップバック：**初見の訪問者が3秒で「自分向きのサイトだ」と判断できる表現になっていますか？**
- 品質チェック：曖昧な表現（「最先端の」「革新的な」「トータルサポート」）は具体化を促す。「何が最先端なのか」「何をどうサポートするのか」を明確にする。

#### サービス/プロダクト説明
- ステップバック：**お客様がこのサービスを使う「Before → After」を教えてください。使う前はどんな状態で、使った後はどう変わりますか？**
- ステップバック：**競合サービスと比較したとき、御社だけが言える「Only 1」は何ですか？**
- ステップバック：**このサービスを導入しない場合、お客様にどんなリスク/損失がありますか？**

#### 会社情報
- ステップバック：**「なぜこの事業をやっているのか」——創業の原体験やきっかけを一文で教えてください。（About/Storyセクションに使います）**
- ステップバック：**御社の文化や価値観を最もよく表すエピソードを1つ挙げるとしたら？**

#### 実績/事例
- ステップバック：**その実績で最もインパクトのある「数字」は何ですか？（例：導入後〇%改善、〇社が採用、〇年の実績）**
- ステップバック：**お客様が「このサービスを選んでよかった」と言ってくれた具体的な言葉はありますか？**

#### CTA周辺テキスト
- ステップバック：**訪問者がCTAボタンを押す直前に感じる「最後の不安」は何ですか？ その不安を解消する一文を添えます。**
  - 例：「無料です」「3分で完了」「しつこい営業はしません」「まずは話を聞くだけでOK」
- ステップバック：**CTA後の流れ（次に何が起きるか）を教えてください。訪問者の期待値を正しく設定します。**

#### FAQ
- ステップバック：**営業やカスタマーサポートで「毎回聞かれる質問」のTop5は？**
- ステップバック：**競合と比較検討している人が聞きがちな質問は？**
- ステップバック：**料金・契約に関する質問で、HPに載せて問題ないものはどれですか？**

#### MVV（ミッション/ビジョン/バリュー）
- ステップバック：**そのミッションを「日常の業務判断」に落とすと、具体的にどんな判断基準になりますか？——抽象的なMVVを訪問者に実感させるための材料にします。**

#### 採用情報
- ステップバック：**御社に入社した人が「入ってよかった」と思うポイントは？ 逆に「ここは覚悟が必要」と思うポイントは？——正直な情報がミスマッチを防ぎます。**

## Phase C：一貫性チェック + 生成前確認

回収が終わったら、以下の品質分析を実施してからユーザーに確認を取る。

### C-1) メッセージ一貫性チェック（エージェントが実施）
```
【チェック項目】
□ Hero見出し ↔ サービス説明 ↔ CTA のメッセージが一貫しているか
□ ターゲットの課題 → 解決策 → 証拠 → CTA の論理が通っているか
□ トーン/ボイスが全テキストで統一されているか
□ 専門用語のレベルがターゲットに合っているか
□ 同じことを違う言い方で書いていないか（表記ゆれ）
□ 「We視点」と「You視点」のバランスは適切か
```

不整合がある場合はユーザーに指摘し、修正案を提示する。

### C-2) コンテンツ充足度チェック
```
【各セクションの情報密度】
- Hero：□ 課題提起 □ 解決策 □ 差別化 □ CTA → 充足度 ___/4
- Services：□ 概要 □ Before/After □ 特長 □ 証拠 → 充足度 ___/4
- About：□ ストーリー □ 数字 □ チーム □ 文化 → 充足度 ___/4
- CTA：□ 行動喚起 □ 不安解消 □ 次のステップ説明 → 充足度 ___/3
```

充足度が低いセクションは、追加質問で補強するか、セクション自体を簡略化するか提案する。

### C-3) 生成前の確認テンプレ
以下をテキストで提示して確認を取る（この時点で修正可能）。

- ページ一覧（順序）
- 各ページのセクション順
- Hero見出し/サブ見出し/CTA（最終案）
- サービス名・要約（カードで見える文言）
- 会社情報の表に出る項目
- お問い合わせ導線（フォーム or メール/電話）
- **メッセージの一貫性チェック結果**
- **コンテンツ充足度チェック結果**

### 不足がある場合：
- 断定が危険な項目（住所/代表/価格/法務）は「未入力なら非表示」または「ユーザーに再質問」。
- 充足度が2以下のセクションは「情報追加」か「セクション省略」かをユーザーに確認する。
