# 日本企業HPデザイン実例ナレッジ

本ドキュメントは、プロトタイプ生成時のデザイン判断を支える「実例パターン集」である。
各セクションの具体的なレイアウト・コピー・UI パターンを、IAタイプ別・業界別に整理する。

---

## 1. セクション別デザインパターン

### 1-1. Hero セクション

#### パターンA：キャッチコピー＋CTA（テキスト中心）
- **構成**: 大見出し → サブコピー（1〜2行） → CTA ボタン（1〜2個）
- **レイアウト**: 中央揃え or 左寄せ、背景はグラデーション / 単色 / 薄い幾何学パターン
- **適合IA**: ia-corporate-basic, ia-pro-service, ia-lp-onepager
- **適合Theme**: theme-minimal-corporate, theme-big-typography, theme-dark-pro
- **実装例**:
  ```
  ┌──────────────────────────────────────────────┐
  │  [ロゴ]  サービス  会社概要  お問い合わせ     │ ← ヘッダー
  ├──────────────────────────────────────────────┤
  │                                              │
  │         ビジネスを、次のステージへ。           │ ← h1（text-4xl〜text-6xl）
  │    テクノロジーで企業の成長を加速させる        │ ← p（text-lg〜text-xl、muted）
  │                                              │
  │      [お問い合わせ]  [サービス詳細 →]         │ ← CTA（Primary + Ghost）
  │                                              │
  └──────────────────────────────────────────────┘
  ```
- **コピー慣例**:
  - 体言止め or 名詞句（「〜を、〜へ。」「〜する〜」）
  - 文字数: 見出し10〜20字、サブコピー30〜60字
  - 句読点を減らし余白で語る

#### パターンB：ビジュアル＋オーバーレイ
- **構成**: フルブリード画像 → 半透明オーバーレイ → 見出し＋CTA
- **レイアウト**: 画像は `object-cover h-[80vh]`、オーバーレイは `bg-black/40` 等
- **適合IA**: ia-corporate-basic, ia-recruit, ia-local-store
- **適合Theme**: theme-editorial-lux, theme-minimal-corporate
- **注意**: 画像素材が高品質でない場合はパターンA にフォールバック

#### パターンC：スプリットレイアウト（左テキスト/右ビジュアル）
- **構成**: `grid grid-cols-1 lg:grid-cols-2`、左にコピー＋CTA、右にスクリーンショットや写真
- **適合IA**: ia-saas-product, ia-pro-service
- **適合Theme**: theme-modern-saas, theme-glass, theme-dark-pro
- **実装例**:
  ```
  ┌───────────────────────┬──────────────────────┐
  │                       │                      │
  │  プロダクト名         │   [スクリーンショット] │
  │  ──────────           │   またはモックアップ   │
  │  一行の説明文         │                      │
  │                       │                      │
  │  [無料で試す]  [詳細] │                      │
  │                       │                      │
  └───────────────────────┴──────────────────────┘
  ```

#### パターンD：数字実績バー付きHero
- **構成**: ヘッドライン → CTA → 横並びの実績数値（3〜4項目）
- **適合IA**: ia-corporate-proof, ia-saas-product
- **適合Theme**: theme-minimal-corporate, theme-modern-saas
- **実装例**:
  ```
  ┌──────────────────────────────────────────────┐
  │        導入企業500社以上の実績                 │
  │        業界トップクラスの〇〇ソリューション     │
  │                                              │
  │              [お問い合わせ]                    │
  │                                              │
  │  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐    │
  │  │ 500+ │  │ 99%  │  │ 24h  │  │ 10年 │    │
  │  │ 導入社│  │ 満足度│  │ 対応 │  │ 実績 │    │
  │  └──────┘  └──────┘  └──────┘  └──────┘    │
  └──────────────────────────────────────────────┘
  ```

### 1-2. Proof / 実績セクション

#### パターンA：ロゴウォール
- **構成**: 「導入企業」見出し → クライアントロゴをグリッド配置（grayscale → hover で color）
- **レイアウト**: `flex flex-wrap justify-center gap-8` / ロゴは `h-8 grayscale opacity-60`
- **適用**: 実績ロゴを持つ企業向け（B2B に特に有効）
- **注意**: ロゴが無い場合は絶対に架空ロゴを作らない → 数値 Proof へ切り替え

#### パターンB：数値ハイライト（Metrics）
- **構成**: 3〜4 個の数値カード / カウンターアニメーション付き
- **レイアウト**: `grid grid-cols-2 md:grid-cols-4 gap-6`
- **数値例**: 「導入社数」「継続率」「対応時間」「業界年数」
- **コピー慣例**: 数値は大きく（text-4xl〜text-5xl font-bold）、ラベルは小さく（text-sm muted）

#### パターンC：テスティモニアル（お客様の声）
- **構成**: 引用文 → 社名・氏名・肩書き → 顔写真（任意）
- **レイアウト**: カルーセル or グリッド（2〜3列）
- **コピー慣例**:
  - 引用符「」で囲む（日本式） or blockquote スタイル
  - 具体的な成果を含む（「〇〇が30%改善」）
  - 社名は「株式会社〇〇」のフルネーム

### 1-3. サービス / 機能セクション

#### パターンA：カードグリッド
- **構成**: セクション見出し → 3〜4列のカード（アイコン＋見出し＋説明）
- **レイアウト**: `grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6`
- **カード構造**: アイコン（上 or 左） → h3（font-semibold） → p（text-sm muted）
- **適合**: ほぼ全 IA。サービス数が 3〜6 の場合に最適

#### パターンB：Bento グリッド
- **構成**: 大小混在のグリッド（1つのメイン＋複数のサブ）
- **レイアウト**: CSS Grid で `grid-cols-4` の複雑配置、メインは `col-span-2 row-span-2`
- **適合Theme**: theme-modern-saas（Bento）
- **適合IA**: ia-saas-product
- **実装例**:
  ```
  ┌─────────────┬──────┬──────┐
  │             │  機能2 │  機能3 │
  │   機能1     │      │      │
  │  （メイン） ├──────┴──────┤
  │             │    機能4      │
  └─────────────┴──────────────┘
  ```

#### パターンC：交互レイアウト（ジグザグ）
- **構成**: 左画像＋右テキスト → 右画像＋左テキスト → 交互
- **レイアウト**: `grid grid-cols-1 lg:grid-cols-2`、偶数行で `lg:order-last` を画像に適用
- **適合IA**: ia-pro-service, ia-corporate-proof
- **適合Theme**: theme-editorial-lux, theme-minimal-corporate

#### パターンD：タブ / アコーディオン
- **構成**: 左にタブメニュー、右に説明エリア
- **適合IA**: ia-saas-product（機能が多い場合）
- **UI**: shadcn/ui の Tabs or Accordion コンポーネントを使用

### 1-4. プロセス / ステップセクション

#### パターンA：水平ステップバー
- **構成**: 3〜5ステップを横並び（番号 → 見出し → 説明）
- **レイアウト**: `flex` or `grid grid-cols-3`、ステップ間を線や矢印で接続
- **実装例**:
  ```
  ┌────────┐     ┌────────┐     ┌────────┐     ┌────────┐
  │  STEP  │ ──→ │  STEP  │ ──→ │  STEP  │ ──→ │  STEP  │
  │   01   │     │   02   │     │   03   │     │   04   │
  │ ヒアリング│  │ 提案   │     │ 実装   │     │ 運用   │
  └────────┘     └────────┘     └────────┘     └────────┘
  ```
- **モバイル**: 縦並びに変更（`flex-col`）

#### パターンB：タイムライン（縦型）
- **構成**: 左に番号/アイコン、中央に縦線、右に説明
- **レイアウト**: `relative` で中央線を `absolute`、各ステップを `flex` で配置
- **適合**: ステップ数が 5 以上の場合、または会社沿革と共用

### 1-5. FAQ セクション

#### 標準パターン：アコーディオン
- **構成**: セクション見出し + shadcn/ui の Accordion
- **レイアウト**: `max-w-3xl mx-auto`（中央寄せ、読みやすい幅）
- **件数**: 5〜10件が適切。多い場合はカテゴリ分け
- **コピー慣例**:
  - Q は「〜ですか？」「〜できますか？」の質問形
  - A は丁寧語で簡潔に（2〜3文）
  - 日本語らしい表現例:
    - 「無料で試すことはできますか？」
    - 「導入までどのくらいかかりますか？」
    - 「セキュリティ対策について教えてください。」

### 1-6. CTA セクション

#### パターンA：フルワイドバナー
- **構成**: 背景色付きバンド → キャッチ → CTA ボタン
- **レイアウト**: `bg-primary text-primary-foreground py-16 text-center`
- **実装例**:
  ```
  ┌──────────────────────────────────────────────┐
  │              ████████████████                 │ ← bg-primary
  │                                              │
  │    まずはお気軽にご相談ください                 │
  │                                              │
  │           [無料相談を予約する]                  │
  │                                              │
  └──────────────────────────────────────────────┘
  ```

#### パターンB：カード型 CTA
- **構成**: Card コンポーネント内に見出し＋説明＋ボタン
- **レイアウト**: `max-w-2xl mx-auto`、影やボーダーで区切り
- **適合**: LP の中間 CTA（スクロール途中での行動促進）

#### CTA コピー慣例（日本語）
- Primary: 「お問い合わせ」「無料相談」「資料をダウンロード」「デモを予約」「応募する」
- Secondary: 「サービス詳細を見る」「もっと知る」「事例を見る」
- 注意: 「今すぐ」は控えめに。日本語サイトでは穏やかな誘導が好まれる傾向

### 1-7. 会社概要セクション

#### パターンA：プロフィールテーブル
- **構成**: dl / table 形式でキーバリューを縦並び
- **必須項目**: 会社名、代表者名、所在地、設立年、事業内容
- **任意項目**: 資本金、従業員数、取引銀行、許認可
- **レイアウト**: `grid grid-cols-[120px_1fr]` or `<dl>` で `dt` / `dd` 配置
- **実装例**:
  ```
  ┌──────────┬───────────────────────────┐
  │ 会社名   │ 株式会社〇〇              │
  ├──────────┼───────────────────────────┤
  │ 代表者   │ 代表取締役 山田 太郎       │
  ├──────────┼───────────────────────────┤
  │ 所在地   │ 東京都渋谷区〇〇 1-2-3     │
  ├──────────┼───────────────────────────┤
  │ 設立     │ 2020年4月                 │
  ├──────────┼───────────────────────────┤
  │ 事業内容 │ ITコンサルティング、...     │
  └──────────┴───────────────────────────┘
  ```

#### パターンB：MVV（ミッション / ビジョン / バリュー）
- **構成**: 大きな見出し → 3カラムまたは縦並びでM/V/Vを表示
- **レイアウト**: `grid grid-cols-1 md:grid-cols-3 gap-8`
- **コピー慣例**:
  - Mission: 「私たちは〜を実現します」（行動宣言）
  - Vision: 「〜な社会/世界を目指して」（未来像）
  - Values: 3〜5 個の行動指針（名詞句 or 体言止め）

#### パターンC：代表メッセージ
- **構成**: 左に代表写真、右にメッセージテキスト＋署名
- **レイアウト**: `grid grid-cols-1 lg:grid-cols-[300px_1fr] gap-8`
- **注意**: 写真がない場合はテキストのみレイアウトで成立させる

### 1-8. お問い合わせセクション

#### パターンA：フォーム＋補足情報
- **構成**: 左にフォーム、右に連絡先/営業時間/地図
- **レイアウト**: `grid grid-cols-1 lg:grid-cols-[1fr_400px] gap-8`
- **フォーム項目（日本語サイト標準）**:
  - お名前（必須）
  - メールアドレス（必須）
  - 会社名（任意 or 必須）
  - 電話番号（任意）
  - お問い合わせ種別（セレクト）
  - お問い合わせ内容（テキストエリア、必須）
  - 個人情報の取り扱いへの同意（チェックボックス、必須）
- **注意**: プロトタイプではフォーム送信は `preventDefault` でアラート表示のみ

#### パターンB：シンプル（フォームのみ中央配置）
- **構成**: `max-w-xl mx-auto` にフォームを配置
- **適合**: LP や小規模サイト

### 1-9. フッターセクション

#### パターンA：カラムフッター
- **構成**: 3〜4カラム（会社情報 / サービス / お知らせ / SNS） → コピーライト
- **レイアウト**: `grid grid-cols-2 md:grid-cols-4 gap-8`
- **必須要素**: ロゴ、コピーライト、プライバシーポリシーリンク
- **実装例**:
  ```
  ┌──────────┬──────────┬──────────┬──────────┐
  │ [ロゴ]   │ サービス │ 会社情報 │ お知らせ │
  │ 一行説明 │ ・機能A  │ ・会社概要│ ・ブログ │
  │          │ ・機能B  │ ・採用   │ ・PR    │
  │          │ ・料金   │ ・アクセス│         │
  ├──────────┴──────────┴──────────┴──────────┤
  │ © 2025 株式会社〇〇  プライバシーポリシー   │
  └──────────────────────────────────────────────┘
  ```

#### パターンB：シンプルフッター
- **構成**: ロゴ → 横並びリンク → コピーライト
- **レイアウト**: 1行 or 2行（`flex justify-between items-center`）
- **適合**: LP、小規模サイト

---

### 1-10. ナビゲーション

#### パターンA：標準ナビ（standard）
- **構成**: 左にロゴ、右にメニュー（4〜6項目） + CTA ボタン
- **モバイル**: ハンバーガーメニュー → スライドインまたはフルスクリーンオーバーレイ
- **スクロール挙動**: `sticky top-0`、スクロール時に `bg-background/80 backdrop-blur`

#### パターンB：ミニマルナビ（minimal）
- **構成**: ロゴ＋ハンバーガーのみ（常時）
- **適合**: LP、デザイン重視サイト
- **適合IA**: ia-lp-onepager, ia-local-store

#### パターンC：メガメニュー（mega）
- **構成**: メニューホバーでドロップダウン（機能カテゴリ＋説明付き）
- **適合IA**: ia-saas-product（機能が多い場合）

## 2. IA タイプ別 実例パターン

### 2-1. ia-corporate-basic（コーポレート標準）

**典型的なユーザー**: 中小〜中堅企業、スタートアップ（シリーズA以降）
**目的**: 名刺代わり＋問い合わせ獲得

#### ページ構成例
```
/ (トップ)
├── Hero（パターンA or B）
├── ServiceHighlights（カードグリッド 3列）
├── Features or 選ばれる理由（3〜4項目）
├── CompanyTeaser（MVV の要約 + 「詳しく見る」リンク）
├── CTA（フルワイドバナー）
└── Footer（カラム型）

/services
├── ServiceGrid（詳細カード）
├── Process（水平ステップ 4段）
├── FAQ（アコーディオン）
└── CTA

/company
├── Overview（プロフィールテーブル）
├── MVV
├── CEO Message（写真＋テキスト）
├── History Timeline（沿革）
└── Footer

/contact
├── ContactForm + Info
└── Footer

/privacy
├── Legal Body
└── Footer
```

#### デザイン判断の指針
- Hero はテキスト中心が安全（画像素材がない場合が多い）
- サービスは 3 つに絞ると見やすい
- 会社概要のテーブルは必ず作る（日本企業サイトの慣例）
- CTA は「お問い合わせ」に一本化

#### よくあるコピーパターン
- Hero: 「〇〇で、ビジネスの可能性を広げる」
- Service: 「私たちのサービス」「提供サービス」
- Company: 「会社概要」「私たちについて」
- Contact: 「お問い合わせ」「ご相談・お見積り」

---

### 2-2. ia-corporate-proof（事例/実績中心コーポレート）

**典型的なユーザー**: B2B企業、SIer、コンサル会社
**目的**: 比較検討時の信頼獲得 → 問い合わせ

#### ページ構成例
```
/ (トップ)
├── Hero（パターンD: 数字実績バー付き）
├── Proof（ロゴウォール or メトリクス）
├── ServiceHighlights（カードグリッド）
├── CaseStudyTeaser（事例3件のカード＋「もっと見る」）
├── CTA
└── Footer

/services
├── ServiceGrid
├── Process
├── Testimonials（お客様の声カルーセル）
├── FAQ
└── CTA

/case-studies
├── CaseStudyGrid（フィルタ付きカード一覧）
└── CTA

/company（ia-corporate-basic と同様）
/contact
/privacy
```

#### デザイン判断の指針
- Proof セクションをファーストビュー直下に配置（信頼の早期獲得）
- 事例ページは必須。件数が少なくても 2〜3 件あれば作る
- テスティモニアルは実名・社名・肩書き必須（匿名は価値半減）
- 数字は「500社+」「99.5%」のように端数を持たせると信憑性が上がる

#### よくあるコピーパターン
- Hero: 「〇〇社以上の導入実績」「業界No.1の〇〇」
- Proof: 「導入実績」「お客様の声」「選ばれる理由」
- Case Study: 「導入事例」「お客様事例」「活用事例」

---

### 2-3. ia-saas-product（SaaS/プロダクト型）

**典型的なユーザー**: SaaS企業、BtoB/BtoCプロダクト
**目的**: 理解 → 比較 → 導入（無料トライアル or デモ）

#### ページ構成例
```
/ (トップ)
├── Hero（パターンC: スプリット、スクショ付き）
├── Proof（ロゴウォール）
├── FeatureBento（Bentoグリッド or カード）
├── UseCases（利用シーン 3〜4パターン）
├── CTA（「無料で試す」）
└── Footer

/product
├── Hero（製品概要）
├── FeatureBento（詳細機能）
├── Integrations（連携サービス一覧）
├── Security（セキュリティ・コンプライアンス）
├── FAQ
└── CTA

/pricing
├── PricingTable（2〜3プラン横並び）
├── FAQ（価格関連）
└── CTA

/company（簡略版）
/contact
```

#### デザイン判断の指針
- スクリーンショットが最重要素材 → なければモック生成 or テキスト中心に切り替え
- Pricing はユーザー提供の情報をそのまま使う（絶対に推測しない）
- 機能数が多い場合は Bento グリッドが効果的
- CTA は「無料で試す」「デモを予約」に統一

#### 料金テーブルパターン
```
┌──────────────┬──────────────┬──────────────┐
│   Free       │   Pro        │  Enterprise  │
│   ¥0/月      │  ¥9,800/月   │   要問合せ   │
│              │              │              │
│  ・機能A     │  ・Free全機能 │ ・Pro全機能   │
│  ・3ユーザー │  ・10ユーザー │ ・無制限     │
│              │  ・優先対応   │ ・専任担当   │
│              │              │              │
│  [始める]    │ [★ 始める]  │ [問い合わせ] │
└──────────────┴──────────────┴──────────────┘
```
- 推奨プランに `★` やバッジ（「人気」「おすすめ」）を付ける
- 「年払い割引」トグルを検討

#### よくあるコピーパターン

## 3. Theme 別デザインガイド

### 3-1. theme-minimal-corporate

**キーワード**: 洗練、信頼、余白、シンプル

#### CSS / Tailwind の特徴
- 余白: `py-20 md:py-32`（セクション間は広く取る）
- 角丸: `rounded-xl`（0.75rem）
- 影: `shadow-sm` or `shadow-none`（控えめ）
- フォント: システムフォント（sans-serif）
- カラー: ブルー系 primary（#1e40af）、スレートグレーの foreground

#### セクション実装の注意
- カードは `border border-border` + `bg-card` で軽く区切る
- アイコンは Lucide（outline スタイル）で統一
- Hero の背景は単色 or 非常に薄いグラデーション
- 文字サイズのコントラストを大きく（見出し vs 本文）

### 3-2. theme-modern-saas

**キーワード**: 先進、軽快、モジュール、UI

#### CSS / Tailwind の特徴
- 角丸: `rounded-2xl`（1rem）
- Bento グリッド: カードサイズを不均一に
- Primary: パープル系（#7c3aed）
- アニメーション: `standard`（hover でスケールや影変化）

#### セクション実装の注意
- Feature セクションは Bento レイアウト推奨
- グラデーション背景を部分的に使用（`bg-gradient-to-br from-primary/5 to-accent/5`）
- コードブロックやターミナル風 UI を取り入れると「先進感」
- アイコンは Lucide outline + 背景円形バッジ

### 3-3. theme-big-typography

**キーワード**: メッセージ、タイポ、余白

#### CSS / Tailwind の特徴
- 見出し: `text-5xl md:text-7xl lg:text-8xl font-bold tracking-tight`
- 行間: `leading-relaxed`
- 余白: 極端に広い（`py-24 md:py-40`）
- Primary: スカイブルー（#0ea5e9）

#### セクション実装の注意
- 見出しが主役。画像よりもテキストのインパクトで勝負
- セクション間に大きな余白 or 区切り線（`border-t`）を入れる
- 本文テキストも `text-lg` 以上で読みやすく
- 写真が少なくても成立するテーマ（テキスト＋余白で構成）

### 3-4. theme-glass

**キーワード**: 透明感、奥行き、未来感

#### CSS / Tailwind の特徴

- 角丸: `rounded-2xl`（1rem）

#### セクション実装の注意
- **背景が重要**: グラデーション背景やメッシュグラデーションの上にカードを乗せる

**キーワード**: 尖り、強コントラスト、太枠、実験

## 5. 日本語サイト特有の慣例

### 5-1. テキスト / コピー
- **敬語レベル**: BtoB は「です・ます」調、LP は「〜しませんか？」の問いかけ調
- **句読点**: 見出しには句読点を付けない場合が多い（体言止め）
- **カタカナ語**: 業界に合わせる（IT は英語混じり OK、伝統業界は日本語寄り）
- **数字**: アラビア数字で統一（「５００」ではなく「500」）
- **住所**: 「〒xxx-xxxx 東京都〇〇区〇〇 x-x-x」の形式
- **電話番号**: 「03-xxxx-xxxx」ハイフン区切り

### 5-2. レイアウト / UI
- **フォームの「必須」表記**: ラベル横に赤い「必須」バッジ
- **プライバシーポリシー同意**: フォーム送信前に必須チェック
- **会社概要テーブル**: 日本企業サイトの定番（dt/dd or table 形式）
- **パンくずリスト**: 複数ページサイトでは推奨（SEO + ユーザビリティ）
- **「トップに戻る」ボタン**: 長いページでは右下にフローティング配置

### 5-3. 法務 / コンプライアンス
- **プライバシーポリシー**: 個人情報保護法に基づく記載が必須
- **特定商取引法表記**: EC / 有料サービスの場合
- **Cookie 同意バナー**: GDPR 対応が必要な場合のみ（日本国内は任意だが増加傾向）

### 5-4. メタ情報 / OGP
- **title**: 「サービス名 | 会社名」の形式
- **description**: 120文字以内で要約
- **OGP 画像**: 1200×630px、サービス名＋キャッチコピーを含む

## 6. レスポンシブデザインガイド

### ブレイクポイント（Tailwind デフォルト）
| プレフィックス | 幅 | 用途 |
|---|---|---|
| (なし) | 0px〜 | モバイル（base） |
| `sm` | 640px〜 | 大型スマホ |
| `md` | 768px〜 | タブレット |
| `lg` | 1024px〜 | ノートPC |
| `xl` | 1280px〜 | デスクトップ |

### モバイルファーストの原則
1. グリッドは `grid-cols-1` → `md:grid-cols-2` → `lg:grid-cols-3`
2. Hero の見出しは `text-3xl md:text-5xl lg:text-6xl` でスケール
3. ナビゲーションは `md` 以下でハンバーガーメニュー化
4. CTAボタンはモバイルで `w-full`、デスクトップで `w-auto`
5. セクション間余白は `py-12 md:py-20 lg:py-24` でスケール

### モバイル特有の考慮
- **電話番号**: `tel:` リンクでタップ発信
- **地図**: iframe は `aspect-video` or `h-[300px]` で固定高
- **テーブル**: 横スクロール or カード形式に変換
- **フォーム**: 入力フィールドは `text-base`（iOS ズーム防止: 16px以上）

## 8. アニメーション / モーション設計

### motionIntensity 別の適用ガイド

| レベル | Framer Motion 設定 | 適用例 |
|---|---|---|
| `none` | アニメーション無効 | IR、厳格な企業サイト |
| `subtle` | fade-in のみ、duration: 0.4s | コーポレート標準、editorial-lux |
| `standard` | fade-in + slide-up、stagger、duration: 0.5s | SaaS、モダン系 |
| `expressive` | 大きな slide、scale、parallax、duration: 0.6-0.8s | LP、ポップ系 |

### 共通実装パターン（Framer Motion）
```jsx
// subtle: フェードインのみ
<motion.div
  initial={{ opacity: 0 }}
  whileInView={{ opacity: 1 }}
  viewport={{ once: true, margin: "-50px" }}
  transition={{ duration: 0.4 }}
/>

// standard: フェードイン + スライドアップ
<motion.div
  initial={{ opacity: 0, y: 20 }}
  whileInView={{ opacity: 1, y: 0 }}
  viewport={{ once: true, margin: "-50px" }}
  transition={{ duration: 0.5 }}
/>

// stagger（カードグリッド等）
<motion.div
  variants={{
    hidden: {},
    show: { transition: { staggerChildren: 0.1 } }
  }}
  initial="hidden"
  whileInView="show"
  viewport={{ once: true }}
>
  {items.map((item, i) => (
    <motion.div
      key={i}
      variants={{
        hidden: { opacity: 0, y: 20 },
        show: { opacity: 1, y: 0 }
      }}
    />
  ))}
</motion.div>
```

### prefers-reduced-motion 対応
```jsx
import { useReducedMotion } from "framer-motion";

function Section({ children }) {
  const shouldReduceMotion = useReducedMotion();
  return (
    <motion.div
      initial={shouldReduceMotion ? {} : { opacity: 0, y: 20 }}
      whileInView={shouldReduceMotion ? {} : { opacity: 1, y: 0 }}
      viewport={{ once: true }}
    >
      {children}
    </motion.div>
  );
}
```

## 9. プレースホルダー戦略

画像素材がない場合のフォールバック：

### Hero 画像なしの場合
1. **グラデーション背景**: `bg-gradient-to-br from-primary/10 via-background to-accent/10`
2. **幾何学パターン**: CSS で dot-pattern や grid-pattern を生成
3. **テキスト中心 Hero** に切り替え（パターンA）

### 人物写真なしの場合
1. **アバター**: `bg-muted rounded-full` + イニシャル文字
2. **テスティモニアル**: 引用テキストのみで構成（写真なし版）

### プロダクトスクリーンショットなしの場合
1. **ワイヤーフレーム風ボックス**: `border-2 border-dashed border-muted rounded-xl`
2. **テキスト + アイコンで機能説明** に切り替え
3. **「画像準備中」のプレースホルダ**: `bg-muted flex items-center justify-center`

### ロゴなしの場合
- テキストロゴ: 会社名を `font-bold text-xl` で表示
- ロゴ部分を `<span className="font-bold text-xl">会社名</span>` で代替
